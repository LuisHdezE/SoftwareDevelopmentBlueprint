# BF-OT-008 — API First and operational QA proposal

Status: PROPOSED; depends on PR #81. Extends BF-P05 and BF-P06, without modifying stable gates or dev-postman-qa skill. Applies to explicitly adopted HTTP API scope, not API-optional products lacking HTTP APIs. Native non-HTTP contracts need separately approved QA strategy.

## Staged deliverables
Before implementation: repository-owned docs/api/ENDPOINTS.md and openapi.yaml; stable operationId, requirement, method/path, authorization, request/response/error contracts. OpenAPI validated before implementation. Initial Postman collection planned/generated from validated contract; final collection follows existing postman_contract phase. Before API QA: postman_collection.json (v2.1), postman_environment.local.json, postman_environment.staging.json, postman_environment.production.json, operation-coverage.json. Before acceptance: API-TEST-REPORT.md and sanitized machine report from pinned runner on isolated runtime. Production template is non-executable by this workflow; no destructive production testing. No credentials committed, even synthetic passwords in the new portable templates: inject at runtime.

## Ownership
Backend maintains inventory, OpenAPI, collection and mapping. QA independently executes and verifies intended success, negative/authentication/authorization, validation, idempotency and chained flows as applicable. Security owns security QA, Auditor verifies exact head and evidence. Reuse ApiBlueprint exporter and dev-postman-qa where compatible; existing ApiBlueprint coverage schema may be transformed explicitly into portable consumer format, not silently rewritten. Generated stubs and mock responses do not certify domain implementation.

## Portable package
The proposal validator consumes docs/api, using ENDPOINTS.md machine-readable Markdown table rows (operationId, method, path, requirement, authorization), OpenAPI paths, collection requests with unique names, coverage mapping, non-secret environment templates. Each operation has exactly one canonical mapped request; additional negative/flow requests are allowed and must refer to a real operation. Request URL raw form uses {{baseUrl}}/path and {{param}} placeholders. Check method/path, operation coverage, per-request test script presence and environment blank credentials. This deliberately supports a restricted portable subset, not every valid Postman/OpenAPI construct. Full OpenAPI lint/schema, semantic assertion quality, runtime response correctness, authorization and actual secret scanning remain separate gates. No network calls or production execution in the validator.

Structural PASS means PACKAGE_READY_FOR_RUNTIME_QA, not api_qa_pass. Runtime report and human review are separate. Do not treat a script containing assertions as evidence they ran. Native exports, runner execution, live route inventory reconciliation and gate integration remain followups. No changes to consumer repos or version markers.
