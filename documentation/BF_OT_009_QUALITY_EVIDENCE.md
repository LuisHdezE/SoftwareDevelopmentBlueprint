# BF-OT-009 — Quality evidence overlay

Status: PROPOSED; depends on #82. Reuse stable catalog/checks.yaml and catalog/gates.yaml, no changes to stable IDs or workflows. This is a supplemental read-only evidence preflight, not an independent QA certification or release authorization.

For an explicitly adopted governed task, freeze repository, full candidate commit, task ID/revision, approved scope and required checks. Derive platform obligations from independently reviewed impact analysis; never omit affected surfaces by declaring them N/A. QA owns functional and runtime evidence, Security owns security evidence, Auditor independently reconciles evidence. All deliveries require QA and traceability, with proportionate tests (documentation-only review is not runtime QA). Affected web requires real browser evidence, HTTP API requires actual Postman/Newman execution, Android/iOS/desktop each require actual platform execution. Architecture conformance and security checks apply to affected implementation and trust boundaries. Public discoverability applies to affected indexable surfaces. No automatic PASS from build success or screenshots alone.

Evidence record binds candidate, task and revision, each obligation, producer role, actual execution type, runner/version, executed count, failure count, artifact path and SHA256. All applicable evidence must be current and nonempty. Artifact paths are confined to evidence directory; symlinks prohibited. Independently authenticate actual execution, scope, role identity, detached evidence ref and candidate identity before gate acceptance. The validator does not authenticate artifacts or verify actual runtime semantics; a digest proves integrity only. No release permission, merge or deploy. Synthetic fixtures never certify a consumer.

Use scripts/validate-quality-evidence.py with a frozen review plan and evidence record. Result READY_FOR_INDEPENDENT_QA_REVIEW is structural only; BLOCKED is fail closed. Browser demo uses Playwright on a local synthetic HTML interface; it proves the runner circuit, not consumer acceptance. Native mobile and desktop runners require later pilot and platform adapters. Stable gate integration and independent audit remain pending.
